//Activity 1 :
==>package.json
1.Contains project details (name, version, author)
2.Stores dependencies with version ranges (^, ~)
3.Manually created & edited by developer
4.Defines scripts (start, test, etc.)
5.Does NOT store sub-dependencies
6.Used when running npm install
7.Flexible → allows different versions to install

==>package-lock.json
1.Contains exact versions of all dependencies
2.Includes sub-dependencies (nested packages)
3.Automatically generated by npm
4.Not meant to be edited manually
5.Ensures same installation for all users
6.Makes builds consistent & reproducible
7.Locks dependencies → no version changes

package.json → Defines dependencies
package-lock.json → Locks dependencies

//Activity 2:
==>dependencies
1.Packages required for running the application
2.Installed in production
3.Used in main code (server/app logic)

==>devDependencies
1.Packages required only for development
2.Not needed in production
3.Used for testing, debugging, building

dependencies → App needs to WORK
devDependencies → Developer needs to BUILD

Activity 1: Why we use Middleware (in Express.js)
1.To process requests before reaching the route handler
2.To modify request (req) and response (res) objects
3.To execute common logic (like authentication, logging)
4.To handle errors globally
5.To control request flow using next()
6.To separate concerns (keep code modular and clean)


Activity 2: Types of Middleware
1.Application-level middleware
-Applied using app.use()
-Runs for all routes or specific routes
2.Router-level middleware
-Applied using express.Router()
-Used for specific route groups
3.Built-in middleware
-Provided by Express
-Example: express.json(), express.static()
4.Third-party middleware
-Installed via npm
-Example: cors, morgan, body-parser
-Error-handling middleware
-Special middleware with 4 parameters: (err, req, res, next)
-Handles errors centrally

Activity 3: Benefits of Middleware
-Improves code reusability
-Makes code modular and maintainable
-Enables centralized error handling
-Helps in security implementation (auth, validation)
-Supports logging and monitoring
-Reduces duplicate code
-Easy to debug and manage request flow
